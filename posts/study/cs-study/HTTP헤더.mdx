# HTTP 헤더란?

HTTP 헤더는 클라이언트와 서버가 HTTP 요청 및 응답 과정에서 추가 정보를 교환하는 중요한 수단이다.<br/>
이들은 요청 또는 응답과 함께 전송되는 메타데이터로, 요청이나 응답의 처리 방식을 지시하거나 필요한 정보를 전달한다. HTTP 헤더는 주로 이름과 값으로 구성된 키-값 쌍의 형태를 취하며, 콜론(':')으로 구분된다.

---

# HTTP 헤더의 종류

HTTP 헤더는 그 용도에 따라 여러 종류로 나눌 수 있다.

## 1.요청 헤더(Request Headers)

클라이언트가 서버에 요청을 보낼 때 포함되는 헤더로, 요청이나 클라이언트 자체에 대한 정보를 제공한다.
- Accept: 클라이언트가 수용할 수 있는 MIME 타입을 지정한다.
- User-Agent: 요청을 보내는 클라이언트 소프트웨어나 사용자 에이전트를 식별한다.
- Authorization: 보호된 리소스에 접근하기 위한 인증 자격 증명을 포함한다.
- Content-Type: 요청 본문의 미디어 타입을 나타낸다.

## 2.응답 헤더(Response Headers) 

서버가 클라이언트의 요청에 응답할 때 포함되는 헤더로, 서버나 응답 자체에 대한 정보를 제공한다.
- Content-Type: 응답 본문의 미디어 타입을 지정한다.
  - Content-Type 헤더는 MIME 타입을 사용하여 데이터의 형식을 나타낸다.
  - 일반적으로 "타입/서브타입" 형태로 구성된다. 예를 들어, HTML 문서는 "text/html", JPEG 이미지는 "image/jpeg"
  - 브라우저는 MIME 타입을 확인하여 해당 파일을 어떻게 처리할지 결정한다. 예를 들어, "text/html"은 웹 페이지로 렌더링하고, "image/png"는 이미지로 표시한다.
- Cache-Control: 응답의 캐싱 동작을 제어한다.
- Set-Cookie: 세션 상태를 유지하기 위해 클라이언트 브라우저에 쿠키를 설정한다.
- Location: 리디렉션 시 요청된 리소스의 새로운 위치를 지정한다.

> MIME 타입이란?
>> MIME 타입은 인터넷에서 전송되는 다양한 종류의 데이터를 식별하기 위한 표준화된 형식이다.<br/>
>> MIME은 "Multipurpose Internet Mail Extensions"의 약자<br/>
>> 본래 이메일 시스템에서 시작되었지만 현재는 웹에서 광범위하게 사용된다.

## 3.일반 헤더(General Headers)

요청과 응답 모두에 사용되며, 메시지에 대한 일반 정보를 제공한다.
- Date: 메시지가 생성된 날짜와 시간을 지정한다.
- Connection: 연결을 유지할지 또는 닫을지를 제어한다.

## 4.엔티티 헤어(Entity Headers)

메시지 본문이나 엔티티에 대한 정보를 제공한다.
- Content-Length: 콘텐츠의 길이를 바이트 단위로 나타낸다.
- Content-Encoding: 응답 본문에 적용된 인코딩을 지정한다.

# HTTP 헤더의 기능

HTTP 헤더는 다양한 기능을 수행하며, 웹 통신에서 중요한 역할을 한다.

- 인증: 'Authorization'헤더를 통해 사용자 인증을 처리한다.
- 캐싱: 'Cache-Control'헤더를 통해 리소스의 캐싱 전략을 제어한다.
- 콘텐츠 협상: 클라이언트가 수용할 수 있는 콘텐츠 타입을 서버에 알리고, 서버는 이에 맞춰 응답을 제공한다.
- 보안: 'Strict-Transport-Security'와 같은 보안 헤더를 통해 웹 애플리케이션의 보안을 강화한다.

HTTP 헤더는 클라이언트와 서버 간의 효율적인 정보 교환을 가능하게 하며, 웹 애플리케이션의 성능과 보안을 향상시키는데 중요한 요소이다.
